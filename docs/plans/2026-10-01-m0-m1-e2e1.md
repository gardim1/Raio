# Implementation plan: M0 -> M1 -> E2E-1

Owner authorisation: 2026-10-01. Each milestone ends with recorded evidence in `docs/STATUS.md`: commands, exit codes, platform, commit, screenshots (kept local), and every check that was **not** performed.

Conventions: identifiers in English; domain logic test-first; one coordinator integrates and commits (owner identity only, verified after every commit); at most one implementation worker plus one read-only reviewer at a time; escalate after two failed attempts at the same blocker.

Design reference lives in `.local/design-reference/` (ignored). Visual comparisons and goldens stay local this round.

## E2E-1 - Real Claude Code session -> Raio

| # | Task | Acceptance |
|---|---|---|
| 2.1 | Capture real hook payloads from the installed Claude Code into ignored `.local/` using a throwaway project with no secrets; produce sanitised fixtures (no prompts, contents, absolute personal paths) and delete the raw captures afterwards. Answer and record: does `timeout` apply to async hooks; are async Stop/SessionEnd hooks lost when `claude -p` exits; is the hook command run through a shell on Windows (quoting of paths with spaces/backslashes); does the Bash result carry an exit code or a separate failure event; does `SessionStart` carry a `source`; is there a prompt id. | Fixtures committed only after manual review for private data; each question answered with evidence. |
| 2.2 | `raio-hook` binary: parse stdin, minimise to event v1, write a temp file inside `inbox/.tmp` and rename into `inbox/` (same volume, bounded retry on sharing violations), caps, one marker file per dropped event (no shared counter), self-timeout, always exit 0. **Never writes raw stdin**: unknown/malformed input is dropped and counted; paths outside the project root become `outside-project`. Ordering within a session is labelled approximate. | `cargo test` contract tests from fixtures: every hook event kind, unknown event, truncated JSON, oversize payload, inbox full, concurrent hook processes, rename failure injection, and sentinel strings planted in prompts/contents/responses that must never appear in the inbox or database. |
| 2.3a | Store: SQLite (WAL), embedded migrations with `user_version`. | `cargo test`: migration applied and reported; reopen is idempotent. |
| 2.3b | Ingestion: dedupe, quarantine of minimised-but-invalid records, delete inbox files only after the DB commit. | `cargo test`: duplicate ids, out-of-order, crash between commit and delete, restart re-ingest. |
| 2.3c | Retention, per-session cap (drop low-value filesystem events first; never failures or sensitive changes), corrupted-database handling. | `cargo test`: cap policy, corrupt file renamed aside and surfaced. |
| 2.4 | Disk consistency and attribution (as implemented: Rust records facts only - hook events and debounced `file.changed`; matching, confidence, staleness and `incomplete` are pure TypeScript projections in `src/features/project/`, see ARCHITECTURE "Evidence and validation semantics"): watcher on the connected project root using `.gitignore` rules, per-path debounce/coalescing; watcher overflow becomes a visible "activity incomplete" state. A reported edit is "reported and consistent on disk" when the same path changes within a window on either side (async hooks can arrive after the watcher); a concurrent unassigned change on the same path lowers confidence. Unmatched changes are `unassigned`. `editGeneration` increments on every non-ignored disk change regardless of author. A `running` validation without a result becomes `incomplete` at session end or timeout. | Tests: reported vs consistent vs unassigned; a human edit inside the window never yields high confidence; a human edit after passing tests makes them stale; stuck `running` becomes `incomplete`; a 10,000-file burst in ignored folders produces at most N events and loses no agent event. |
| 2.5 | Projection (TS): classifier (paths -> heuristic groups), layout, notices, validation states, insights. **Edges are out of E2E-1**: the map shows "relationships unknown"; TS/JS import edges move to E2E-2. | Domain tests including "no telemetry", "unsupported adapter", "unknown attribution", parallel activity, session without `session.ended` -> `incomplete`. |
| 2.6 | Replay from persisted events via `compileReplay`; IPC commands (`list_sessions`, `session_events`, `project_map`) and an ingest notification. | Integration test: hook binary with a fixture on stdin -> inbox -> DB rows -> projection snapshot. |
| 2.7 | Connect/disconnect Claude Code for one project via `.claude/settings.local.json`: diff preview, backup, preserve existing entries, re-read/compare/atomic-rename write (Claude Code writes this file too), remove only Raio's. Warn if `git check-ignore` says the file is not ignored. Bounded in time: the hook is inert when Raio's heartbeat is older than N days, and the inbox has a TTL. Tell the user hooks apply to new sessions. | `cargo test` for merge, backup, idempotence, removal, malformed existing file, concurrent modification; a missing hook binary does not block Claude Code. |
| 2.8 | Real run: connect the throwaway project, run a short `claude -p` session on the owner's authenticated subscription without permission bypass (plus an interactive session if `-p` loses async end hooks), open Expanded, play "View changes", restart, replay again. Without exit codes, validations show "observed, result unknown", never passed. | Screenshots, event ids, DB row counts, identical replay after restart. |
